# Bugo Sync List – Render Deployment & Operations Guide

**System:** Web-Based Resident Assistance Management System for Barangay Bugo, Cagayan de Oro City  
**Architecture:** React.js (Vite + TypeScript + Tailwind CSS + OpenStreetMap/Leaflet) · Node.js + Express.js · MySQL · Prisma ORM · JWT · Bcrypt · RBAC  
**Target Production Platform:** **Render** (`render.yaml` Blueprint / Render Web Service)

> **Optional Services Note:** Firebase Cloud Messaging (FCM) and Cloudinary file storage are **not implemented** in this codebase (notifications are persisted in the relational database notification queue, and document uploads use validated base64/file metadata checks). Placeholder keys remain commented out in `.env.example` should you add them in a future phase.

## A. Localhost Development (Before Deploying to Render)

### 1. Prerequisites
- **Node.js** `v20+` or `v22+` and `npm` `v10+`
- **MySQL** `8.0+` running locally on `127.0.0.1:3306` *(optional for quick local JSON evaluation)*

### 2. Create Local Database & User
Run inside your local `mysql` shell:
```sql
CREATE DATABASE IF NOT EXISTS barangay_bugo_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'bugo_user'@'localhost' IDENTIFIED BY 'CHANGE_ME_LOCAL_DB_PASS';
GRANT ALL PRIVILEGES ON barangay_bugo_db.* TO 'bugo_user'@'localhost';
FLUSH PRIVILEGES;
```

### 3. Configure Environment Variables
```bash
cp .env.example .env
```
Edit `.env` for localhost:
- Set `NODE_ENV="development"`
- Set `PORT="3000"`
- Set `APP_URL="http://localhost:3000"`
- Set `CORS_ORIGIN="http://localhost:3000"`
- Set `DATABASE_URL="mysql://bugo_user:CHANGE_ME_LOCAL_DB_PASS@127.0.0.1:3306/barangay_bugo_db"`
- Generate strong `JWT_SECRET` and `HMAC_SECRET`:
  ```bash
  node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
  ```

### 4. Install Dependencies, Migrate & Seed MySQL via Prisma
```bash
npm install
npm run prisma:generate
npm run prisma:migrate:deploy
npm run prisma:seed
```
*(Fallback note: If `DATABASE_URL` is omitted during local evaluation, the server automatically operates in JSON local fallback mode via `data/db.json`, while full MySQL persistence activates automatically once `DATABASE_URL` is configured.)*

### 5. Starting and Stopping Locally
- **Start Development Server (React Vite + Express API on port 3000):**
  ```bash
  npm run dev
  ```
  Open `http://localhost:3000` in your browser.
- **Start Local Production Simulation:**
  ```bash
  npm run build
  NODE_ENV=production npm start
  ```

## B. Render Production Deployment (Single Supported Platform)

This repository includes a preconfigured **`render.yaml`** Blueprint for **Render Web Services**. Render hosts the unified Node.js + Express backend and Vite-compiled React frontend with automatic HTTPS/TLS, health monitoring, and zero-downtime deploys.

### 1. Render Build & Start Configuration
Render executes the following lifecycle commands (defined in `render.yaml`):
- **Runtime:** `node` (Node.js 20+)
- **Region:** `singapore` (closest Render region to Cagayan de Oro City for low latency)
- **Build Command:**
  ```bash
  npm ci && npx prisma generate && npm run build
  ```
  *(Compiles the React frontend into `dist/index.html` + `dist/assets/*` via Vite and bundles the Express API server into `dist/server.mjs` via `esbuild`.)*
- **Start Command:**
  ```bash
  npm start
  ```
  *(Executes `node dist/server.mjs` on Render's injected `PORT`.)*
- **Health Check Path:** `/api/health`

### 2. Required Render Environment Variables
Configure these in the **Render Dashboard → Environment** tab (or via Blueprint sync):
- `NODE_ENV="production"`
- `FORCE_HTTPS="true"` *(enforces HTTPS redirect behind Render's TLS proxy via `X-Forwarded-Proto`)*
- `APP_URL="https://<your-service>.onrender.com"`
- `CORS_ORIGIN="https://<your-service>.onrender.com"`
- `DATABASE_URL="mysql://<user>:<pass>@<mysql-host>:<port>/barangay_bugo_db?sslaccept=strict"`
- `JWT_SECRET="<64+ char random hex secret>"` *(auto-generated by `render.yaml`; server refuses production startup if missing or default)*
- `JWT_EXPIRES_IN="2h"`
- `BCRYPT_ROUNDS="12"`
- `HMAC_SECRET="<64+ char random hex secret>"` *(auto-generated by `render.yaml`; server refuses production startup if missing or default)*
- `SEED_ADMIN_PASSWORD` / `SEED_RESIDENT_PASSWORD` *(set strong initial credentials before seeding production DB, then rotate or remove)*
- `GEMINI_API_KEY` *(optional — for AI ID document verification; falls back to server heuristics if omitted)*

*(Note: The Bugo Disaster Hazard Map uses **OpenStreetMap + Leaflet & Nominatim** and does not require any map API key.)*

### 3. Production Prisma Migrations on Render
Before starting or after provisioning your MySQL database, run migrations from Render Shell (or locally targeting the production `DATABASE_URL`):
```bash
npx prisma generate
npx prisma migrate deploy
```
Only run `npm run prisma:seed` on initial empty database provisioning (uses idempotent `upsert`, safe against overwriting existing production users).

### 4. HTTPS / TLS & Security Hardening Active in `server.ts`
- **Helmet HTTP Security Headers**: Sets CSP (allowing OpenStreetMap tiles), `X-Frame-Options`, `X-Content-Type-Options`, HSTS, etc.
- **Strict CORS Allowlist**: Restricts cross-origin requests exclusively to `CORS_ORIGIN` / `APP_URL`.
- **Trust Proxy & HTTPS Enforcement**: `app.set('trust proxy', 1)` + `FORCE_HTTPS="true"` redirects HTTP requests to HTTPS (`301`) behind Render's load balancer.
- **JWT & RBAC Middleware**:
  - `authenticateJWT` verifies `Authorization: Bearer <token>` via `jsonwebtoken`.
  - `requireRole('admin')` protects administrative actions (application approval/disqualification, voucher disbursement, resident verification/banning, profile change decisions, announcements, census updates, archive management).
  - `requireSelfOrAdmin` restricts resident mutations to their own user ID.
- **Bcrypt Hashing (`bcryptjs`)**: All new registrations, password changes, and Prisma seeds hash passwords using Bcrypt (configurable rounds, default `12`) while keeping legacy verification backward compatibility.
- **Brute-Force Rate Limiting**: 5 failed login attempts lock out an IP for 60 seconds.
- **Structured Error Logging & Monitoring**: Writes JSON error events to `stderr` (viewable in Render Logs) and `logs/error.log` without leaking stack traces in production HTTP responses. `/api/health` exposes database connectivity, latency, and uptime for Render's health checker.

## C. Database Backups & Recovery Procedures

### Automated Backup (`mysqldump` + gzip + 14-day retention)
```bash
DATABASE_URL="mysql://user:pass@host:3306/barangay_bugo_db" bash scripts/backup_mysql.sh
```
*(You can also enable automated daily snapshots on your managed MySQL 8 database provider or trigger `scripts/backup_mysql.sh` from a Render Cron Job.)*

### Recovery / Restore Procedure
```bash
gunzip -c backups/barangay_bugo_YYYYMMDD_HHMMSS.sql.gz | \
  mysql -h <MYSQL_HOST> -P <MYSQL_PORT> -u <MYSQL_USER> -p barangay_bugo_db
```
After restoring, verify schema alignment with `npx prisma migrate status` and check `/api/health`.

## D. Render Domain & Custom Domain Guidance (Barangay Bugo)

### Does Barangay Bugo Need a Custom Domain?
**No — a custom domain is optional.**  
Render automatically provisions an HTTPS URL (`https://<your-service>.onrender.com`) with a managed TLS certificate. A custom domain (e.g., `assist.barangaybugo.gov.ph`) can be attached anytime in **Render Dashboard → Settings → Custom Domains** via CNAME/A records without code changes (simply update `APP_URL` and `CORS_ORIGIN` in Render Environment Variables).

## E. Step-by-Step Render Deployment Checklist
1. Push this repository (including `render.yaml`) to GitHub or GitLab.
2. In the **Render Dashboard**, choose **New → Blueprint** (or **New → Web Service**) and connect the repository.
3. Provision a TLS-enabled **MySQL 8** database and copy its `DATABASE_URL` (`?sslaccept=strict`).
4. Set `DATABASE_URL`, `APP_URL`, `CORS_ORIGIN`, `SEED_ADMIN_PASSWORD`, and `SEED_RESIDENT_PASSWORD` in Render's Environment settings (`JWT_SECRET` and `HMAC_SECRET` are auto-generated by `render.yaml`).
5. Deploy on Render — Render runs `npm ci && npx prisma generate && npm run build` and starts `npm start`.
6. Open **Render Shell** (or connect locally with `DATABASE_URL`) and run:
   ```bash
   npx prisma migrate deploy
   npm run prisma:seed
   ```
7. Run the verification suite against your Render URL:
   ```bash
   VERIFY_BASE_URL="https://<your-service>.onrender.com" npm run verify:deploy
   ```
8. Confirm `https://<your-service>.onrender.com/api/health` returns `status: "ok"`, `database.mode: "mysql-prisma"`, and `database.connected: true`.
9. Verify Admin login, Resident login, RBAC enforcement, OpenStreetMap Hazard Map rendering, application creation, refresh persistence, and zero console/network errors.
